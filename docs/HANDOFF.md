# G10 Control 开发交接

最后更新：2026-10-19。交接点：**用户要求暂停自动唤起实验，整理并公开源码。不要自动继续硬件测试。**

## 1. 已经解决的问题

当前样机是可直接通过 Windows 11 配对的 BLE G10 / 3K 空中飞鼠。飞鼠移动与点击原先就正常。已发现并验证 ATVV 语音服务：

| 角色 | UUID |
|---|---|
| 服务 | `ab5e0001-5a21-4f05-bc7d-af01f617b664` |
| TX | `ab5e0002-5a21-4f05-bc7d-af01f617b664` |
| AUDIO | `ab5e0003-5a21-4f05-bc7d-af01f617b664` |
| CONTROL | `ab5e0004-5a21-4f05-bc7d-af01f617b664` |

红键观察到控制通知 `08`，主机能力协商后可进入语音会话。实际已收到音频、完成 IMA ADPCM 解码，并把 PCM 写入 WASAPI 的 CABLE Input。豆包选择 CABLE Output 后，用户已确认能识别文字。

链路已经稳定到可以手动唤起豆包使用，后续应保留 `g10_audio_bridge.py`、`Controller`、解码器和缓冲队列，先加接口与状态，不要为迁移 Rust 重写整条链路。采样和帧参数的结论只适用于已测样机，不能推广到所有 G10。

## 2. 当前软件真实状态

- 已有可启动的 Python + pywebview / WebView2 + React / TypeScript 桌面外壳；不是 Tauri 版本。
- BLE / 音频服务是独立子进程，受桌面外壳监督；包含互斥和重复桥接进程检查。
- 有设备页、语音页、只读按键页、设置页、日志 / 诊断导出入口、托盘和原子配置保存。
- 默认持续运行，安全停止会释放音频流、清理本次订阅并关闭引用；不会删除蓝牙配对。
- 按键映射还不能设置动作。普通键盘和鼠标不应被观察范围外的逻辑处理。
- 自动唤起尚未成功，UI 已标注实测未通过；不能把 BLE 音频活动和电平当作豆包录音已启动。
- 当前用户开机自启入口已实现；自动重连、休眠恢复、安装包与发行回归尚未完成。

## 3. 自动唤起失败的证据链

1. 相同 ChatGPT 文本框中，选豆包输入法后，实体右 Alt 能显示录音界面。
2. `SendInput(VK_RMENU)` 和 `E0 38` 扩展扫描码都只触发普通 Alt 提示；未观察到豆包 CABLE 捕获。
3. 普通权限向豆包状态栏 `PostMessage` 返回错误5。只读令牌查询确认普通进程为 medium，豆包进程为 high、UIAccess=true；这解释消息被权限隔离拒绝。
4. 用户明确授权临时管理员对照。提权后消息可以投递，但没有观察到录音；同权限右 Alt 仍失败，且已确认发送与释放。
5. 只读 UIA / MSAA 检查：状态栏只有根 pane，没有 InvokePattern，也没有原生 IAccessible 子控件；没有可靠按钮接口。
6. 离线检查本机豆包0.9.2.7机器码，语音键钩子读取 `KBDLLHOOKSTRUCT.flags` 并对 bit4=1 直接走 `CallNextHookEx`，跳过语音快捷键处理。因此继续调整模拟 Alt 或提权不解决这个版本的注入键过滤。
7. `btn_voice` 的静态回调追踪到内部委托对象 `vtable+0x20`，尚未确定外部协议。不得猜 `RpcPipe_SimpleMessage` 参数，不得远程执行程序内部函数。

这些结论来自当前安装版本与本机实测。公开仓库仅保留文字交接，不上传豆包安装文件、机器码转储、设备日志、录音或原用户界面截图。

## 4. 停在什么地方

独立探针已准备 `--trigger mouse`：实际移动指针到已核验的可见状态栏麦克风位置，检查遮挡，点击后恢复原位置；录音成功后尝试结束并检查捕获状态。它会产生鼠标模拟输入。

**这个候选实现没有实测，也没有并入正常桥接。** 用户在授权前选择暂停，因此不能启动该路径，不能把之前的临时管理员授权当作长期后台授权。`start_doubao_permission_test.ps1` 是人工诊断入口，不是安装脚本，不应被自动启动。

模拟键盘 / 定向窗口消息路线已经有失败证据。恢复开发后应先回顾这些证据，避免要求用户重复相同无效测试。

## 5. 接手后的实施顺序

1. 阅读本文件、`README.md` 和 `ATVV_PROTOCOL.md`。在新机创建自己的本地配置，先跑无硬件测试与前端构建。
2. 在用户明确愿意配合时，复验已知手动桥接。普通使用保持自动唤起关闭。
3. 若继续自动唤起，先取得目标操作授权；优先验证真实麦克风 UI 入口或厂家公开接口。鼠标实验需确认目标可见、焦点、开始、停止和原光标恢复，不只检查 API 返回值。
4. 若鼠标方案有效，再评估是否符合长期使用目标。不要让整个桌面应用长期管理员运行，不要直接把一次性探针当成生产后端。
5. 将语音开始 / 停止动作抽象为后端接口，保持 BLE 会话与音频缓冲独立；以真实 CABLE 捕获状态为启动依据，避免吞首音，松键先排尾音再结束。
6. 设备映射先采样逐键身份和事件。只能识别的按钮标记待检测；需要拦截原功能时先评估按设备方案并另行授权。
7. 再实现双击 / 长按 / 多步骤动作、重连、休眠恢复，最后才打包安装并做真实回归。

## 6. 必须保留的边界

- 不修改固件，不扫描未知业务命令，不主动解除 / 重建配对。
- 不覆盖当前飞鼠移动、鼠标点击和已解决的搜索弹窗相关实现。
- 不安装 Interception 或其他内核驱动；任何驱动 / 系统设置变更需用户明确同意。
- 不自动设置 Windows 默认麦克风 / 扬声器，不自动发送识别文字。
- 不把 Raw Input 只读观察包装成设备独立映射。
- 运行管理员探针、产生新的键鼠模拟输入或让用户按键测试时，必须说明动作并等待用户；暂停状态不能默认恢复。
- 不提交本机 `local-settings.json`、`output/`、用户配置、录音或设备清单。

## 7. 代码、测试与资源管理

根目录单元测试覆盖能力解析、ATVV 白名单与状态转换、通知二进制边界、解码、缓冲排空与重采样、声音相关性、豆包控制失败清理、鼠标不可见 / 遮挡时拒绝操作；桌面测试覆盖配置与公开API边界。测试主要使用替身，不等于硬件验证。

一次实际出现过 `capture_active` 被辅助函数错误缩进吞入的问题；后来补了真实 `WindowsBackend` 类的回归检查。保留这个测试，不要只用替身验证全部后端。

BLE 不同进程不能抢占同一会话。安全退出通过停止信号触发；遇到清理超时，不能直接杀进程绕过 CCCD 恢复。只恢复本次改动的订阅值。

## 8. 公开快照与本机开发副本的差异

- 移除了真实蓝牙地址与 Windows 音频端点 ID，新增 `local_config.py` / `configure_local.py`；空配置拒绝连接和无目标按键监听。
- 不包含个人报告生成器、原始报告、声音、设备清单、二进制参考程序、商品照片与反汇编转储。
- 用自绘 SVG 按键示意图替代商品照片。
- 应用数据目录改为 G10ControlPublic；相邻未复制的 AxonKey 参考检查是可选项。
- 合成音频路由证明必须在目标机器重新生成。公开快照不能携带原开发机器的证明充当新机验证。
- 首次独立Windows CI发现旧解码器运行时仍读取相邻参考仓库中的标准IMA表；公开版已将标准数值表内置并做等价性校验，解码数学逻辑不变，不再依赖该参考目录。
- 公开快照只完成离线测试与构建回归，尚未对泛化后的配置入口做另一轮真实硬件测试。原始本机工作副本保留，不受发布过程影响。
